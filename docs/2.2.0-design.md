# 2.2.x implementation contract (2.2.1 candidate)

Historical design/evidence only. Current settings and qualification are documented in README.md and docs/DEVELOPMENT.md; this is not the current release contract.

Baseline: 2.1.11, SHA-256 `1fc8a5017ed0c996776a988f1ac145ac49e803e182da083e77cfcd7c41830708`.
Production is out of scope. Runtime evidence and qualification scope are recorded
in `staging-results/2026-10-04/2.2.1/FINAL-REPORT.md`; this contract is not production approval.

## Boundaries

* `enable=false`: return before creating the datasource, coordinator, event handlers,
  timers or database commands. Runtime mixin hooks also bypass PDC.
* Item domain OFF: inventory, armor, offhand and ender chest must all be OFF.
  Do not capture, clear, normalize, apply, or write item/pending columns. Existing
  database escrow remains untouched; re-enabling requires operator reconciliation
  of the locally owned items against the retained database representation.
* No final data save: freeze the current session, capture enabled domains once on
  the server thread, and compare against the **actual durable row under the
  coordination lock**, after preceding per-player operations. Active item
  transients always prevent this release. Only exact enabled-domain equality
  permits clean release without a PlayerData update; otherwise mark recovery.
* Advancements: replace criterion progress directly, preserving millisecond
  timestamps; rebuild tracking/visibility without grantCriterion, rewards, or
  empty-advancement reward execution. Statistics: registry-validated replacement,
  never addition. Disabled domains must not access their trackers.
* Recovery: the ACQUIRE transaction never resolves unclean ownership. Manual is explicit
  only. Safe mode requires a durable final-transaction receipt, not a reason
  string, deadline, source unreachability, or checkpoint existence. Unsafe
  `last_checkpoint` requires explicit acknowledgement and a separate audited
  transaction; it does not claim World/MySQL reconciliation.
* Automatic is a separate availability-first, risk-acknowledged resolution, also
  invoked before a fresh same-login acquire. It rejects a live lease, missing
  checkpoint, unknown/invalid ownership reason, fence/revision mismatch, too-old
  checkpoint, insufficient delay, or exhausted durable attempt budget. Audit is
  atomic with resolution. Attempt reservation commits separately; resolution
  re-locks and rechecks every guard after reservation. No pool connection or lock
  is retained across the phases. Safe never downgrades to automatic.
* Periodic defaults to 10 seconds, dirty-only. Explicit seconds wins; old JSON
  with minutes only converts to seconds. Server ticks compare scalars/items;
  progress/stat/recipe use mutation counters, not full scans. Item equality
  includes in-place NBT edits and retained playerScreen cursor. Dirty epochs are
  independent of snapshot sequence; old completion cannot clean later changes.
  Disabled domains are not read. Play-time stats/effect countdowns are changes.
* Profile properties/signatures and recipe IDs/options use real replace payloads.
  Authenticated name/global scoreboard renaming is unsupported; a differing
  saved display label fails closed. Legacy identity-only/recipe placeholder
  preserves current state once, then saves real payloads.

## Safety and ordering

All Minecraft capture/apply is server-thread-only; workers receive immutable DTOs.
All ownership/recovery transitions lock coordination before PlayerData. Periodic
A and final B share the UUID serial queue. Stale callbacks cannot mutate a new
session. Unclean expiry remains RECOVERY_REQUIRED unless explicit configured
automatic policy or a safe durable proof resolves it. Legacy flags are never
reset by migration; NULL checkpoint producer is labelled 2.1.11-compatible
legacy in audit, not treated as proof of a particular binary SHA.
An ambiguous final COMMIT may only be accepted if its operation/session/fence,
revision and complete enabled-domain payload are proven by committed DB evidence.

## SAVE entrypoints

Initial login uses a server-thread local snapshot before READY (no live GUI).
Periodic, death and dimension/respawn use read-only checkpoint overlays. Disconnect,
shutdown and superseded-session finalization use the same ownership-transfer
capture (or the no-final-save comparison above). Source recovery requires an
explicit verified snapshot, never a normal-login fallback.

The fixed 2.2.1 artifact was tested on isolated MySQL 8.0.46 and Minecraft 1.18.2.
Manual/safe and acknowledged automatic contracts remain deliberately distinct.
